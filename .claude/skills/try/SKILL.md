# try: 実践コマンド

## 引数

$ARGUMENTS にはエントリファイルのパス、またはトピック名が渡される。
例: `/try entries/2026-03-24.md` または `/try Claude Code hooks`

## やること

1. **対象の特定**: 引数がファイルパスならそのエントリを読む。トピック名なら `entries/` 内を検索する。
2. **実践プランの提示**: エントリの「試すなら」セクションを元に、具体的な実行ステップを提示する。
3. **ユーザー確認後に実行**: 許可が出たら、以下を行う:
   - 必要なコードを `experiments/YYYY-MM-DD-topic-slug/` に生成
   - 可能であれば実際に実行（bash, node, etc.）
   - 実行結果をキャプチャ
4. **結果の記録**: 実験フォルダにエントリと同名のファイルを生成（実行内容・結果・観察メモ）
5. **エントリの更新**: 元のエントリの `感想・考察` 欄に2〜3行の主観的まとめを追記し、実験ファイルへのリンクを添える。詳細な実行ログは実験ファイル側に書く。ステータスを `tried` に更新する。

## 実験フォルダの構造

```
experiments/YYYY-MM-DD-topic-slug/          # エントリファイル名と同名のフォルダ
├── YYYY-MM-DD-topic-slug.md                # 実行ログ・詳細（エントリと同名）
└── [実践コード・出力ファイル]                # コードがある場合のみ追加
```

- フォルダ名・メインファイル名は対応するエントリファイル名と一致させる
- README.md は作成しない（概要はメインファイル冒頭に記述する）
- コードなしの検証でもフォルダ構造は統一する

## 重要な注意

- CLAUDE.md のスキルセットを参照し、C#/TypeScript/Unity に関連する場合はそのコンテキストでコードを生成する
- 破壊的操作（ファイル削除、設定変更等）は必ず確認を取る
- APIキーやクレデンシャルが必要な場合は、手順を示すだけで自動入力しない
