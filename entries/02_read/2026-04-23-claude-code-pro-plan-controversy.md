# Claude Code Proプラン剥奪騒動（2026年4月）の全容

- 2026年4月21日、AnthropicがClaude Code（$20 Proプラン）の料金ページとドキュメントから「Claude Code」の記載をひっそり削除し、Max専用（$100+）とする変更を実施
- 数時間後に元に戻され、新規登録の約2%に影響するテストだったと説明されたが、公式アナウンスなしの変更に批判が集中
- 将来的にProプランでのClaude Code利用制限が行われる可能性を示唆しており、プラン選択の見直しを促した

## 自分への関連度: B

## 感想・考察

### A/Bテストとしての方法論的問題

「新規Proユーザーの2%にClaude Codeを提供しない」というA/Bテストは、そもそもテスト設計として不適切ではないか。一般的にA/Bテストは「同等価値のバリエーション比較」（UI、文言、レイアウト等）であり、提供サービスを減らすのは実験ではなく単なるダウングレードに近い。

ただし、業界慣習としてSaaSの価格・パッケージング最適化で新規サインアップ向けのfeature gatingテストが行われること自体はある（Stripe、Notion等で実施報告あり）。問題は方法論よりも「料金ページを黙って書き換える」という不誠実な実装方法にあると考える。**減らす実験は、減らされた側にも認識されないと「実験」として成立しない**。

### 適切なA/Bテスト設計案

同じビジネス目的（Max転換率の効果測定）を達成しつつ、今回の問題を回避する設計：

1. **上限到達時のアップセル文言テスト**: Claude Codeは全Proユーザーに提供したまま、利用上限時の表示メッセージだけを分岐。サービス内容は変えずメッセージングだけのテスト。リスク最小で示唆も大きい
2. **同価格・構成違いのプラン選択テスト**: 新規サインアップ画面で同じ$20で2構成（Claude Code込み vs 無し+別特典）を並べて選ばせる。「奪われた」感が出ない
3. **Pro Lite追加によるカニバリゼーション測定**: 既存Proは維持、$15のPro Liteを追加して並列販売。「減らす実験」ではなく「選択肢を増やす実験」になる

Anthropicの実際の手法は、これらと比べて「Claude Codeがあったら選んだか」という情報量が得られず、信頼コストも高く、コスパの悪い設計だった。

### 代替措置の有無確認

ソース3記事すべてを確認した結果、**Claude Code削除に対する代替の優遇措置（メッセージ数増、別機能解放、価格据え置き特典等）は一切なかった**ことが判明。3本目のZenn記事では「告知ゼロ、移行期間ゼロ」と明示されている。

「Anthropicともあろう企業が補償を考慮しないはずがない」という直感は外れた形になる。考えられる解釈：

- 実験初期段階で補償設計が詰まっていなかった（だから数時間で撤回）
- 「Claude Code無しの需要弾力性」を測るため、変数を増やしたくなかった

いずれにせよ、Anthropicの実験設計としては**雑だった**と評価せざるを得ない。同様の方向性（Pro→Max誘導）は今後も続く可能性が高いため、Maxプラン継続の判断は引き続き妥当。Pro利用者であれば月の利用量とMax移行コストの比較は定期的にチェックする価値がある。
