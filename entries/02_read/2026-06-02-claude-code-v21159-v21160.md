# Claude Code v2.1.159〜v2.1.160: 設定ファイル書き込みのセキュリティ確認とgrep後Edit改善

## 3行要約

- v2.1.160で、シェル起動ファイル（`.zshenv`/`.zlogin`/`.bash_login`）や `~/.config/git/`、コード実行を許す各種ビルドツール設定（`.npmrc`/`.yarnrc*`/`bunfig.toml`/`.bazelrc`/`.pre-commit-config.yaml`/`.devcontainer/` 等）への書き込み前に確認プロンプトが入るようになった（意図しないコマンド実行の防止）。
- Editのread-before-editチェックが、単一ファイルの `grep`/`egrep`/`fgrep` 実行でも満たされるようになり、grepで中身を見た直後に別途Readする手間が不要に。
- 動的ワークフローのトリガーキーワードが `workflow` → `ultracode` にリネーム（「workflow」という語ではもう起動しない／自分の言葉で依頼すれば従来通り起動）。Windows/WSL周りのクリップボード・背景セッション・IME・file:///リンク等のバグ修正多数。v2.1.159は内部改善のみ。

## 自分への関連度: A

セキュリティ確認プロンプトはサプライチェーン/設定ファイル汚染対策（関心領域#3）に直結し、acceptEditsモードでの安全性が上がる。grep後にRead不要になる改善は日々のClaude Code操作のテンポを実際に変える。Windows環境のバグ修正も自分の環境（VSCodeネイティブ拡張版）に効く可能性があり、即アップデート対象。

## 詳細

- **セキュリティ強化**: シェル起動ファイル/git設定への書き込みに確認プロンプト。さらに `acceptEdits` モードでも、コード実行権限を与えるビルドツール設定ファイル書き込み前に確認するようになった。
- **Edit/grep連携**: 単一ファイルへの `grep`/`egrep`/`fgrep` がread-before-editを満たす。
- **`ultracode` リネーム**: 最新CHANGELOG（2.1.160）時点でトリガーキーワードは `ultracode`（プロンプト入力中はバイオレットでハイライト）。`CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE` は削除されno-op化。`/effort ultracode` はxhigh非対応モデルでは提供されない。
- **バグ修正（抜粋）**: WSLでのcopy-on-selectがOSC 52ではなくPowerShell interop経由でWindowsクリップボードに書けるよう修正。背景セッションの会話履歴喪失・再実行、`claude --bg` のsocket missing、Windowsでの入力不応答、CJK IMEの表示位置、`file:///C:/...` リンクの破損、非ASCIIなディレクトリ/ブランチ名でのvoice mode接続失敗などを修正。
- JetBrainsプラグインのインストール提案を起動時に表示しないよう変更。

## 試すなら

1. `claude update`（または使っているインストール方法）で v2.1.160 へ更新。
2. `npm` 系プロジェクトでEditを走らせ、`.npmrc` 等への書き込み時に確認プロンプトが出るか確認。
3. grepで関数を確認した直後にEditして、Read不要で編集できるか体感する。
4. 動的ワークフローを使うなら `ultracode` キーワード／`/effort ultracode` の挙動を確認。
