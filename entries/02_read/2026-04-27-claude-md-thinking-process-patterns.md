# AI駆動開発のための CLAUDE.md 設計パターン — 5つの思考プロセス型

## 3行要約

- CLAUDE.md を「AI への指示書」ではなく「AI との契約書」として磨く5つのパターン。一般論回避・自己批判付与・セッションログの git 自動保存・時刻再取得・主観優先の意思決定ログ
- 注目は「AI の平均的で無難な回答に思考が引っ張られるのを防ぐ」設計。戦略判断時には "ユーザー自身の仮説を1問だけ確認させる" ルールで一般論化を抑制
- 各パターンは独立導入可能。前作（hikariclaude01 の7テンプレート）が「構造のテンプレ」なら本作は「思考プロセスのテンプレ」

## 自分への関連度: A

「自己批判を添えさせる」「主観→根拠→AI補強の順で意思決定ログを書かせる」は、Claude Code の出力品質を上げる方向性として独自性が高い。一般論回避ルールは、ゲーム開発の設計判断（特定エンジン・特定プラットフォーム特有の制約）で AI の汎用回答に流されがちな問題を直接緩和する。

## 詳細

### 5つのパターン

**1. 一般論で答えさせない設計**
- 戦略判断を伴う問いに対して、"ユーザー自身の仮説を1問だけ確認する" ルールを CLAUDE.md に設定
- AI の平均的で無難な回答に思考が引っ張られるのを防止
- 例: 「どのフレームワークが良い？」と聞かれたら、まず「あなたの仮説は何ですか？」と1問返す

**2. アウトプットに自己批判を添えさせる設計**
- 提案末尾に "最も弱い前提" や "この戦略が負けるシナリオ" を記述させる
- 一般論化の度合いを自動検出し、出力全体を相対化する仕組み
- 自己批判が空虚な定型文になる場合は CLAUDE.md の指示が弱い兆候

**3. セッションログを自動で git に残す運用**
- 毎ターン `logs/` に議論内容を記録し、自動で git commit/push
- 数ヶ月前の判断理由を素早く検索可能に
- Claude Code 側では Hook（PostToolUse 等）で実装可能

**4. 時刻依存判断の前に時刻を再取得させる**
- "今日"・"明日" などの判断前に "必ず最新の時刻を確認" を CLAUDE.md に記載
- セッション開始時の古い時刻情報による誤判断を防止
- このナレッジベースの `currentDate` 注入と同じ思想

**5. 意思決定ログを「主観→根拠→AI補強」の順で書かせる**
- 自分の直感と一次情報を優先し、AI の分析は補強材料に
- 数ヶ月後の読み返しで "あの時の自分の感覚" が再現可能に
- AI 補強を最初に書くと自分の思考が AI に引っ張られる
