# Claude Code v2.1.161〜v2.1.166: fallbackModel設定・バージョンガードレール・プラグイン一覧コマンド追加

## 3行要約

- v2.1.166で `fallbackModel` 設定が追加。プライマリモデルが過負荷時に最大3つのフォールバックモデルを順序付けで試行する機能で、可用性が上がる。グロブパターンによるツール拒否ルール・クロスセッションメッセージングのセキュリティ強化・`MAX_THINKING_TOKENS=0` 対応も含む。
- v2.1.163でバージョンガードレール設定（`requiredMinimumVersion` / `requiredMaximumVersion`）と `/plugin list`（`--enabled`/`--disabled` フィルター付き）コマンドが追加。フック機能拡張・背景セッション更新処理の改善・`/btw` 回答の「c to copy」ショートカットも入った。
- v2.1.162で `claude agents --json` に `waitingFor` フィールドが追加されエージェントの待機状態をJSONで取得可能に。Windsurf対応がDevin Desktopに変更。v2.1.165はバグ修正・信頼性向上のみ。

## 自分への関連度: A

`fallbackModel` はサブスク環境での過負荷時のフォールバック制御として実践的。VSCodeネイティブ拡張環境でのバグ修正（ターミナル・認証・UI）が自分の環境に直接効く可能性あり。バージョンガードレールはチーム/プロジェクト設定のCLAUDE.mdで活用できる。

## 詳細

### v2.1.166（2026-06-06）
- **`fallbackModel` 設定**: プライマリモデル過負荷時に最大3つのフォールバックモデルを順序付きで試行。managedSettings 経由で設定可能
- **グロブパターンによるツール拒否**: ツール拒否ルールにグロブパターンが使えるように
- **クロスセッションメッセージングのセキュリティ強化**
- **`MAX_THINKING_TOKENS=0` 対応**: 思考トークンを完全に無効化できるように
- ターミナル、認証、UIのバグ修正多数

### v2.1.163（2026-06-05）
- **バージョンガードレール**: `requiredMinimumVersion` / `requiredMaximumVersion` managed settings が追加。プロジェクトで特定バージョン範囲を強制可能
- **`/plugin list` コマンド**: `--enabled`/`--disabled` フィルター付きでインストール済みプラグイン一覧を表示
- **「c to copy」ショートカット**: `/btw` の生Markdownをクリップボードへコピー
- 背景セッションの更新処理改善（アップデート後にコールドスタート待機が不要に）
- フック機能の拡張、auto-modeのデータ流出検出精度向上（リポジトリ内容の大量転送を特定）
- `rm -rf $HOME`（`HOME` にトレーリングスラッシュがある場合）のブロック漏れを修正

### v2.1.162（2026-06-04）
- **`claude agents --json`** に `waitingFor` フィールド追加（エージェントが何を待機しているかJSONで取得可能）
- リモートコントロール表示の改善
- Windsurf → Devin Desktop の対応変更
- Windows権限ルール処理の修正

### v2.1.161（2026-06-03）
- OTEL_RESOURCE_ATTRIBUTESのメトリクスラベル化
- 並列ツール実行の信頼性向上
- Linuxクリップボード動作改善
- v2.1.160から引き続きのシェル起動ファイル書き込み確認プロンプト関連の修正

### v2.1.165（2026-06-05）
- バグ修正と信頼性改善のみ（機能追加なし）

## 試すなら

1. `claude update` で v2.1.166 に更新する
2. CLAUDE.md またはプロジェクト settings に `fallbackModel` を設定し、フォールバックの動作を確認する（例: `"fallbackModel": ["claude-sonnet-4-6", "claude-haiku-4-5"]`）
3. `/plugin list --enabled` でインストール済み・有効なプラグインの一覧を確認する
4. `claude agents --json` の `waitingFor` フィールドを確認して並列セッションの待機状態を把握する
