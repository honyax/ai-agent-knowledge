# Claude Code v2.1.196〜v2.1.197: `.mcp.json` 自動起動の制限、バックグラウンドジョブのデータ損失修正

## 3行要約

- v2.1.196〜197（6/29〜30 リリース）で、`claude mcp list/get` が **リポジトリの `.mcp.json` を自己承認された設定として自動起動しない**ように修正。委託されたリポジトリの `.mcp.json` を信用しすぎていた認可の穴を塞いだ形。
- **バックグラウンドジョブの transcript 保護**: 従来、特定のクリーンアップ処理が進行中の transcript を削除してしまうバグがあり、バックグラウンドセッションが crash/中断した際に会話が失われるリスクがあった。今回、クリーンアップパスをより堅牢化。
- **並列リクエスト時の rate-limit warning 誤発火修正**、Sonnet 5 デフォルト化（v2.1.197、[[2026-07-01-claude-sonnet-5-release]] 参照）も同時リリース。

## 詳細

### `.mcp.json` 自動起動の制限（セキュリティ）

- 従来: リポジトリの `.mcp.json` に書かれた MCP サーバーが、`claude mcp list/get` 実行時に **リポジトリの自己承認だけで自動起動**していた。
- 今回: この自動起動経路を閉じ、明示的な承認フローを経由させる。
- [[2026-07-03-mcp-supply-chain-token-theft]] の「悪意ある設定ファイル書き換え」攻撃とは別系統だが、「リポジトリ側の設定を無条件に信用しない」という同じ方向性の強化。

### バックグラウンドジョブの信頼性向上

- **transcript 削除バグ修正**: 特定のクリーンアップパスが進行中の transcript を削除してしまう問題を修正。
- **wake 時のデータ損失修正**: バックグラウンドジョブを wake する際、transcript probe が実際の transcript を誤読して**会話を完全削除し元のプロンプトを再実行してしまう**バグを修正。現在はファイルを退避するだけで削除しない。
- [[2026-07-01-claude-code-v21198-background-agents-auto-pr]] のような長時間 background agent 運用にとって重要な信頼性改善。

### Rate-limit 警告の誤発火修正

- 並列リクエスト実行時に rate-limit 警告が誤ってトリガー・カウントされていたバグを修正。

## 感想・考察

### 修正の範囲: 通常セッションではなく CLI サブコマンド経由の抜け穴（2026-07-03）

「`.mcp.json` に定義していても勝手に接続しないようになるのか」という問いを検討。結論は「大枠では合っているが、より正確には特定の CLI サブコマンド経由の抜け穴を塞いだもの」。

**今回の修正**: `claude mcp list` / `claude mcp get` という CLI コマンド実行時、従来はリポジトリの `.mcp.json` に書かれたサーバーを「リポジトリが自己承認したもの」とみなし、確認なしで自動起動していたバグを修正。この経路を閉じ、明示的な承認フローを通すようにした。

**推測（[[2026-07-03-mcp-supply-chain-token-theft]] の実地確認時に読んだ `~/.claude.json` の構造から）**: 通常のセッション起動時は元々ゲートがあった可能性が高い。各プロジェクトの設定に以下のフィールドが存在することを確認済み:

```json
"enabledMcpjsonServers": [],
"disabledMcpjsonServers": [],
"hasTrustDialogAccepted": true
```

これは「プロジェクトを開いた時に `.mcp.json` のサーバーを信頼するか確認する trust dialog」が既に存在し、回答がキャッシュされている構造を示唆する。つまり **普段の対話的な起動では元々「勝手に接続」はされておらず**、今回の修正は trust dialog を経由しない **別の抜け道**（`claude mcp list/get` コマンド経由）を塞いだもの、と解釈するのが妥当。
