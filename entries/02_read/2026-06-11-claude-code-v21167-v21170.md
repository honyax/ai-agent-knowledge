# Claude Code v2.1.167〜v2.1.170: Fable 5対応・safe mode・/cdコマンド・post-sessionフック

## 3行要約

- v2.1.170でClaude Fable 5（Mythosクラスを一般利用向けに安全化したモデル → [[2026-06-11-claude-fable-5-mythos-5-release]]）に対応。VSCode統合ターミナル等から起動した際にセッショントランスクリプトが保存されない問題も修正。
- v2.1.169で `--safe-mode` フラグ（`CLAUDE_CODE_SAFE_MODE`）が追加。CLAUDE.md・プラグイン・skills・hooks・MCPサーバーなど全カスタマイズを無効化して起動でき、トラブルシューティングの切り分けに使える。`/cd` コマンド（プロンプトキャッシュを壊さずセッションの作業ディレクトリを移動）と `disableBundledSkills` 設定（バンドルskill・ワークフロー・ビルトインスラッシュコマンドをモデルから隠す）も追加。
- v2.1.169ではself-hostedランナー向け `post-session` ライフサイクルフック（作業スナップショットやログ出力用）、enterprise管理MCPポリシーが再接続時に適用されない問題の修正、Windowsでの `claude -p` のskillスキャン起因の遅延修正など。v2.1.167/168はバグ修正のみ。

## 自分への関連度: A

`--safe-mode` は「設定が原因か本体が原因か」の切り分けに即使える運用ツール。`/cd` はモノレポや複数プロジェクトを跨ぐ作業でキャッシュ維持したまま移動できるのが地味に効く。Fable 5対応はv2.1.170更新の直接の動機になる。

## 詳細

- `--safe-mode`: ブラウザの「拡張機能なしで起動」に相当。挙動がおかしいときにまずこれで再現確認 → 再現しなければカスタマイズ側を疑う、という手順が確立できる。
- `/cd`: セッション途中でworking directoryを変えてもプロンプトキャッシュが切れない設計。従来は別ディレクトリ作業 = 新セッションが基本だった。
- `disableBundledSkills`: チーム配布時に「自前のskillだけ見せたい」ケースや、コンテキスト削減目的で使える。
- 他の修正: JetBrains IDE 2026.1+のターミナルちらつき修正、remote sessionがworker登録中のバックエンド瞬断で永久スタックする問題の修正、`claude agents` 一覧でURL入力によるセッションフィルタ対応。

## 試すなら

1. `claude update` で v2.1.170 以上へ更新
2. `claude --safe-mode` で起動し、普段との挙動差（コンテキスト量・skill一覧）を確認
3. セッション中に `/cd ../other-project` を実行し、キャッシュ維持のまま移動できるか確認
4. `/model` で Fable 5 を選んで動作確認（6/22までProプラン内で無料）
