# Claude Code v2.1.140-v2.1.143 — Agent View 後続強化・Fast Mode が Opus 4.7 既定・プラグイン依存解決と HTML 通知 hook

## 3行要約

- v2.1.139 で公開された Agent View を中心に、**`claude agents` への `--add-dir`/`--settings`/`--mcp-config`/`--plugin-dir`/`--permission-mode`/`--model`/`--effort`/`--dangerously-skip-permissions` フラグ追加**（v2.1.142）、バックグラウンドセッションの sleep/wake 後復活・OS sleep を idle と誤検出する問題の修正など、並列ワークフローの実用化を進める修正多数
- v2.1.141 で **hook の `terminalSequence` 出力フィールド**（hook から desktop notification/bell/ウィンドウタイトルを送信）、**`continueOnBlock`**（PostToolUse hook の reject 理由を Claude にフィードバックして turn 継続）、**hook の `args: string[]`**（exec 形式、quoting 不要）が追加。**Rewind menu に「Summarize up to here」**（途中までの context を圧縮）も登場
- v2.1.143（2026-05-15）で **Fast mode のデフォルトが Opus 4.6 → Opus 4.7 に切替**。プラグイン依存解決（`claude plugin disable` が依存元プラグインの有無を検知して拒否、`enable` で transitive 依存を自動 enable）、**`worktree.bgIsolation: "none"` 設定**（worktree が実用的でない repo でバックグラウンドセッションを直接 working copy で動かす）、Windows での PowerShell tool の `-ExecutionPolicy Bypass` 既定有効化、Stop hook が連続 8 ブロック後に warning で turn 終了するキャップ

## 自分への関連度: A

VSCode ネイティブ拡張+Windows ユーザかつ Skill ベース運用の自分にとって、複数の修正が直撃:

- **PowerShell tool 既定有効化（v2.1.143, Bedrock/Vertex/Foundry 利用者向け）と `-ExecutionPolicy Bypass`**: Windows 環境での Bash 代替実行に大きく影響。ローカル Anthropic API ユーザは恩恵が限定的だが、社内 Bedrock 経由の検証で有用
- **Fast mode が Opus 4.7 既定化**: `/fast` 切替時に最新モデルを使うのが既定に。Opus 4.7 ベストプラクティス（2026-04-29 エントリ）との整合性が上がる
- **Rewind menu の "Summarize up to here"**: catch-up Skill 実行時に途中で context が膨らんだ際の compress 手段が標準化。autocompact-trap（2026-03-31）への対処手段が増えた
- **hook の `terminalSequence` / `continueOnBlock`**: catch-up・try Skill の完了通知や Pre/Post hook の責務分離に直接使える。特に `continueOnBlock` は「Post hook で reject 理由を返して Claude に修正させる」設計が公式サポートされた意味で大きい
- **agent view の安定化**: 2026-05-12 で Agent View エントリを書いた直後の修正群。empty session の自動 retire（5分）、background session の sleep/wake 復活、retire→wake で `--bg --dangerously-skip-permissions` 維持。自分の並列運用パイプラインに直撃する

## 詳細

### v2.1.143（2026-05-15）の主な変更

**新機能・既定変更:**
- Fast mode のデフォルト Opus 4.7（`CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE=1` で 4.6 にピン留め）
- プラグイン依存解決: `claude plugin disable` が依存元 plugin の存在を copy-pasteable hint 付きで拒否、`enable` で transitive 依存を自動 enable
- `/plugin` marketplace browse pane で per-turn/per-invocation の token cost を表示
- `worktree.bgIsolation: "none"` 設定: バックグラウンドセッションが `EnterWorktree` なしで working copy を直接編集（worktree が実用的でない repo 向け）
- Windows: PowerShell tool が `-ExecutionPolicy Bypass` を自動付与、Bedrock/Vertex/Foundry で既定有効化
- バックグラウンドセッションが idle wake 後に model/effort 設定を維持
- Shift+Tab で auto mode を cycle に含める

**重要修正:**
- Stop hook が連続ブロック時に永久ループする問題を 8 連続で warning 付き turn 終了に修正（`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` で override）
- `/loop` idle 中の Esc/Ctrl+C で wakeup pending をキャンセル可能に
- `/goal` evaluator が background shell/subagent 実行中にも fire していたバグ修正
- agent view から session 削除しても transcript file が残るバグ修正
- 2.1.136 regression: markdown table の cell wrap が vertical key-value layout に fallback していた問題

### v2.1.142

- `claude agents` のフラグ大幅追加（上記）
- Fast mode Opus 4.7 既定（先行）

- `CLAUDE_CODE_PLUGIN_PREFER_HTTPS`: GitHub plugin source を SSH ではなく HTTPS で clone

- `claude agents --cwd <path>`: session list を directory 単位で絞る
- `/feedback` に直近 24h / 7日 のセッションを含めるオプション
- **Rewind menu の "Summarize up to here"**: 途中までの context を要約圧縮し直近 turn を維持
- auto mode の permission dialog が `permissions.ask` ルール由来のプロンプトを明示
- IDE 接続時の "view diff in your IDE" オプション復活

### v2.1.140

- Agent tool の `subagent_type` matching を case/separator insensitive に
- `/goal` が `disableAllHooks`/`allowManagedHooksOnly` 設定下で silently hang していたバグ修正
- `claude --bg` の "connection dropped mid-request" 修正
- `/loop` が完了通知ありの background task に対して redundant wakeup を schedule していた問題修正

## 感想・考察

### PowerShell tool 既定化の影響範囲

「最近 Claude Code が PowerShell を多用するようになった」という体感の主因を整理:

- **本エントリの v2.1.143 変更（`-ExecutionPolicy Bypass` 自動付与、Bedrock/Vertex/Foundry で既定有効化）は、Pro プラン（Anthropic API 直接）ユーザには直接影響しない**
- 実際の転換点は [v2.1.126（2026-05-04）](../02_read/2026-05-04-claude-code-v21126.md) の「PowerShell 7 を primary shell として正しく検出」。これ以降、Windows + PowerShell 7 環境ではシステムプロンプトに `Shell: PowerShell` が明示され、Bash よりも PowerShell tool が優先される挙動に変わった
- 歴史的経緯: [v2.1.84（2026-03-26）](../04_tried/2026-03-26-claude-code-v2183-v2184.md) で PowerShell tool が opt-in プレビュー登場 → v2.1.119/120 で auto-allow 修正・`/env` 適用 → **v2.1.126 で primary shell 化** → v2.1.143 で host-managed 環境で既定有効化、という段階的展開

### Bash allowlist との二重管理問題への対処

既存の Bash 前提 allowlist が育っているため、PowerShell tool への切替は実質「二度手間」になる。対処として **プロジェクト CLAUDE.md に「Bash tool を優先」する指示を明記**:

- グローバル CLAUDE.md ではなくプロジェクト CLAUDE.md に置くことで、将来別プロジェクトで PowerShell 優先にする余地を残す
- 例外条件（PowerShell 固有 cmdlet、ユーザーが明示指示した場合）を明文化することで、必要時のフォールバックは確保
- 別解として `fewer-permission-prompts` skill で PowerShell allowlist を半自動構築する手もあるが、Bash で代用可能な範囲ではメンテ対象を増やしたくないため不採用

### 他の変更点について

`terminalSequence` hook や `continueOnBlock` は理論上有用だが、現状 hooks をほぼ活用していないため後回し。`worktree.bgIsolation: "none"` は本リポジトリには相性が良いが、Pro プランかつ並列 background session を普段使いしていないため優先度は低い。Fast mode の Opus 4.7 既定化は黙って恩恵を受ける形でよい。
