# CLAUDE.md / Skills / Agents を「変更頻度・呼び出し方・粒度」で3層に整える設計パターン

## 3行要約

- Claude Code の設定ファイル肥大問題に対し、CLAUDE.md（基盤層）・Skills（手順層）・Agents（タスク層）を **変更頻度・呼び出し方・粒度の3軸で分離** する設計パターンを提示した記事
- 配置基準: CLAUDE.md は「全タスクに適用される普遍ルール（200行以下推奨）」、Skills は「キーワードで起動する手順（事前条件と完了条件を明記）」、Agents は「並列実行可能でステートレスなタスク」
- 著者チームでは CLAUDE.md を 800行 → 180行に圧縮しつつ Skills を 8 → 22 個へ展開。重複と「どこに書くべきか分からない」問題が解消した

## 自分への関連度: A

すでに自分は CLAUDE.md・Skills・Hooks を活用しているが、ナレッジベース運用が長くなるにつれ「これは CLAUDE.md に書くべきか、Skill に分けるべきか」の判断が経験則で揺れている。本記事の3軸（変更頻度・呼び出し方・粒度）は判断を機械的にする補助線になる。特に「変更頻度」での分離は、CLAUDE.md のような頻繁に追記されるファイルがコンテキストを食い続ける問題を直接緩和する。Level 5 育成記事（2026-04-23）や 7 テンプレート集（2026-04-27）が「育て方」「テンプレ集」だったのに対し、本記事は「分け方」を提供する点で補完的。

## 詳細

### 3層の責務定義

| 層 | 内容 | 変更頻度 | 呼び出し方 | 粒度 |
|----|------|----------|------------|------|
| **CLAUDE.md（基盤層）** | コーディング規約・命名規則・禁止事項など普遍ルール | 低（月1〜） | 全セッションで自動ロード | 大（プロジェクト全体） |
| **Skills（手順層）** | デプロイ・バグ調査・コードレビュー等のワークフロー | 中（週1〜） | キーワード起動 | 中（タスク種別） |
| **Agents（タスク層）** | 自動コードレビュー・ドキュメント生成等の独立実行単位 | 中〜高 | 明示呼び出し（並列可） | 小〜中（単一責務） |

### 配置の判断ツリー

著者は配置に迷ったときの3つの問いを提示している:

1. **このルールは全タスクに適用されるか？** → Yes なら CLAUDE.md
2. **特定キーワードで発動する手順か？** → Yes なら Skill
3. **独立した作業として並列実行できるか？** → Yes なら Agent

### 設計原則

> 「変更頻度・呼び出し方・粒度のいずれかが異なるものを混ぜない」

これにより、CLAUDE.md に手順詳細が紛れ込んだり、Skill に普遍ルールが書かれたりする「層の汚染」を防ぐ。

### 実践成果

- CLAUDE.md: 800行 → 180行（77.5% 削減）
- Skills: 8個 → 22個（責務境界を明確化した結果として増加）
- 副次効果: 「ここに書いて良いか」迷う時間が減り、ドキュメント化のハードルが下がった

## 試すなら

1. 現在の CLAUDE.md を上から読み、各セクションを「普遍ルール／手順／独立タスク」のどれに該当するか分類する
2. 「手順」に該当するセクションを `.claude/skills/` 配下のファイルに分離（キーワードを `description` に明記）
3. 「独立タスク」に該当する責務（例: コードレビュー）があれば Agent として `.claude/agents/` に切り出す
4. CLAUDE.md は普遍ルールだけ残し、200行以下を目標に圧縮
5. 1〜2週間運用して、新しいルールの追記時に判断ツリーで配置先が即決まるかを観察
