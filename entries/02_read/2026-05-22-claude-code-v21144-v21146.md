# Claude Code v2.1.144〜146 — バックグラウンドセッション安定化、PowerShell 既定強化、/code-review 系コマンド再編、PR URL からの /resume

## 3行要約

- v2.1.144 はバックグラウンドエージェントの安定化が中心。起動ハング・Windows のロックアップ・macOS のファイルアクセス・stop hook のループを修正し、`claude --bg` で開始したセッションも `/resume` で再開できるようになった。PowerShell tool は `-ExecutionPolicy Bypass` を渡すよう変更（`CLAUDE_CODE_POWERSHELL_RESPECT_EXECUTION_POLICY=1` でオプトアウト）。
- v2.1.145 で `claude agents --json`（稼働中セッションを JSON で列挙、status bar やセッションピッカー向け）、`/plugin` の Discover/Browse がインストール前にコマンド・エージェント・skills・hooks・MCP/LSP をプレビュー、`/resume` の検索で PR URL からセッションを特定可能に。
- v2.1.146 では Windows PowerShell の「command line is invalid」回帰（2.1.124 起因）、MCP のページネーション、バックグラウンドセッションが許可済み権限を再要求する不具合など 15件以上を修正。なお当初本要約に書いていた「`/simplify`→`/code-review` 改名」は本ロールアップ範囲ではなく v2.1.147 以降の出来事で、しかも単純な改名ではなかった（下記「訂正: /simplify と /code-review の関係」参照）。

## 自分への関連度: S

Windows ネイティブ拡張版で日常的に使う環境のため、PowerShell の ExecutionPolicy 自動回避と「command line is invalid」回帰修正は直接効く。`/simplify` は手元の利用可能 skill に今も出ており、リファクタリング用途で継続利用できる（`/code-review` への一本化ではなく役割分担。下記「訂正」参照）。バックグラウンドセッションの `/resume` 対応も並列実行運用に関わる。

## 詳細

- PowerShell tool の Bedrock/Vertex/Foundry 向け Windows 既定有効化は v2.1.144 で入った（`CLAUDE_CODE_USE_POWERSHELL_TOOL=0` でオプトアウト）。直接 API 利用なら従来通り Bash 優先のままだが、`-ExecutionPolicy Bypass` 付与は Windows での PowerShell 実行失敗を減らす方向。
- 「Windows で Git Bash 不要（不在時は PowerShell を shell tool として使用）」「`claude ultrareview [target]`」「`claude project purge [path]`」は v2.1.120（4月末 Week 18）由来で本ロールアップの新規ではない。本リポジトリの自分のプロジェクト設定では Bash tool 優先のため、PowerShell 既定化の影響は限定的だが挙動の前提として把握しておく。

### 訂正: /simplify と /code-review の関係（CHANGELOG 原文で確認）

当初この要約では「v2.1.146 で `/simplify` を `/code-review` に改名」と書いたが、CHANGELOG 原文を確認したところ事実と異なっていた。正しい経緯は以下（いずれも本ロールアップ v2.1.144〜146 より後）。

- **2.1.147**: `Renamed /simplify to /code-review. It now reports correctness bugs at a chosen effort level (e.g., /code-review high); pass --comment to post findings as inline GitHub PR comments. The old cleanup-and-fix behavior has been removed`
- **2.1.152**: `/code-review --fix now applies review findings to your working tree after the review, surfacing reuse, simplification, and efficiency suggestions; /simplify now invokes /code-review --fix`（`/simplify` が復活し `/code-review --fix` のエイリアスに）
- **2.1.154 / 2.1.157**: `/simplify now runs a cleanup-only review (reuse, simplification, efficiency, altitude) and applies the fixes, instead of running the full /code-review --fix bug-hunting review`

結論として、**現在は両コマンドが別々の役割で併存している**。

- `/simplify` = リファクタリング・品質整理専用（再利用性・簡素化・効率・altitude）。バグ検出はしない。修正を適用する。
- `/code-review` = correctness バグ検出が主目的。effort level（low〜max / ultra）指定可、`--comment` で PR インラインコメント、`--fix` で working tree に適用。

つまり「改名で `/simplify` が消えた」のではなく、一度 `/code-review` に統合 → その後 cleanup 専用ツールとして再分離された。リファクタリング用途では引き続き `/simplify` を使うのが正しい。

## 試すなら

1. `claude --version` で v2.1.146 以降に更新されているか確認。
2. `/code-review`（バグ検出・effort level 指定可）と `/simplify`（cleanup 専用）を同じ変更差分に対してそれぞれ実行し、用途の違いと出力差を確認。
3. `claude agents --json` を叩いて稼働セッションの JSON 形式を確認（status line 連携の素材になるか検討）。
4. バックグラウンドセッション（`claude --bg`）→ `/resume` の再開フローを軽く試す。

## 感想・考察

読み込み時に気になった3点を深掘りした際のやり取りメモ（2026-05-30）。

### バックグラウンドセッションの権限ダイアログの扱い

「裏で動いているのに許可をどう求めるのか」という疑問。調べた結論:

- `claude --bg` やエージェントビューで起動しても権限が全許可になるわけではなく、起動時の permission mode と `settings.json` の許可ルールをそのまま引き継ぐ（v2.1.143「`permissions.defaultMode` を尊重」、v2.1.141「現在の permission mode を保持」）。
- 許可ルールに無いツールを使おうとすると、その場でダイアログを出せないため **セッションは一時停止して応答待ち（parked）** になる。`claude agents` ビューや `/resume` で再アタッチしたときに保留中のプロンプトを解決する。v2.1.147「既に許可した権限を再要求する不具合の修正」もこの設計が前提。
- 実運用では止まらないよう、**事前に allowlist を整備**（`fewer-permission-prompts` skill が用途に合致）、**auto モードで起動**、または信頼できる隔離環境で **`--dangerously-skip-permissions`** で起動、のいずれかにするのが基本。
- 自分（Pro / VSCode 拡張版 / hooks ほぼ未使用）の入口としては、まず `claude agents` で稼働セッションを眺めてから軽いタスクを `--bg` で投げる流れが無難。

### 「PowerShell 既定強化」の中身は2つ

- (1) v2.1.144 で Bedrock/Vertex/Foundry 経由の Windows 環境で **PowerShell tool が既定オン**（`CLAUDE_CODE_USE_POWERSHELL_TOOL=0` でオプトアウト）。ただし自分は直接 API 利用かつ本リポジトリは Bash 優先運用なので影響は小さい。
- (2) PowerShell tool がコマンド実行時に **`-ExecutionPolicy Bypass` を付与**するようになり、Windows の実行ポリシー（Restricted/RemoteSigned 等）由来の失敗を回避（`CLAUDE_CODE_POWERSHELL_RESPECT_EXECUTION_POLICY=1` でオプトアウト）。これはプロセス単位の回避でシステム設定を書き換えるものではない。PowerShell tool を使う場面でのみ効く。

### /simplify と /code-review の誤記訂正

エントリの「改名」記述が誤りだったため CHANGELOG 原文で訂正（詳細は本文「訂正」節）。要点は **「改名」ではなく「一度統合 → cleanup 専用として再分離」で、現在は別々に併存**。リファクタリング用途では引き続き `/simplify` を使うのが正しく、`/code-review` に乗り換える必要はない、という当初の直感どおりだった。

教訓: changelog の「Renamed A to B」は時系列の途中スナップショットに過ぎず、その後の再分離・再導入で現状が変わっていることがある。要約に取り込む前に最新の CHANGELOG と実際の skill 定義を突き合わせるべき。
