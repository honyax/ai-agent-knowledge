# Claudeトークン消費を抑える「原始人」口調テクニック — 最大80%削減

## 3行要約

- システムプロンプトやCLAUDE.mdで「原始人のように短く話せ」と指示するだけでトークン消費が68〜80%削減できる
- 「です・ます」「丁寧な説明」「まとめ」などの礼儀的な出力を省略させることで、実質的なコンテンツ密度は維持しつつトークンを大幅に節約
- Claude Code のSkillとして実装するとワンコマンドで切り替えられる

## 自分への関連度: A

長時間のClaude Codeセッションでは文脈圧縮（autocompact）が発動するまでのターン数を稼ぎたい。Skillとして組み込めば即使えるアプローチ。CLAUDE.mdに常時適用するかSkillで切り替えるか検討価値あり。

## 詳細

### テクニックの概要

Claudeに対して「原始人（genshijin）口調」で話すよう指示するプロンプトを使う。具体的には:

```
あなたは原始人です。短い言葉だけ使います。
余計な説明なし。挨拶なし。まとめなし。コードだけ。結果だけ。
```

このような指示により:
- 冒頭の「かしこまりました」「承知しました」系の出力がなくなる
- 末尾の「以上です」「何かあればお気軽に」系の出力がなくなる
- 説明の冗長な言い換えが省略される

### 削減率の実績

記事によると:
- 通常の会話: **68%削減**
- コード生成タスク: **最大80%削減**
- 実質的な情報密度（コード・データ部分）はほぼ変わらず

### Claude Code での実装方法

**方法1: CLAUDE.mdに常時適用**

```markdown
## 出力スタイル
- 短く、簡潔に
- 挨拶・まとめ・礼儀的な枕詞は不要
- コードと結果のみ
```

**方法2: Skillとして切り替え可能にする**

`.claude/skills/primitive.md` を作成:
```
今から原始人モードで話します。
短い言葉のみ。挨拶なし。まとめなし。結果とコードのみ出力します。
```

`/primitive` で切り替え。

### 注意点

- 長い説明が必要な場面（設計議論・複雑なデバッグ）では不向き
- コードレビューや簡単な実装タスクには特に効果的
- ユーザー側の指示プロンプトも短くする（自分のメッセージも長文にしない）ことでさらに効果増

## 試すなら

1. CLAUDE.mdに「短く簡潔に、挨拶・まとめ不要」の一行を追加
2. 通常タスクで実行してトークン使用量をステータスラインで確認
3. 追加前後の同タスクでコスト比較
4. 効果があればSkillとして `/concise` などのコマンドで切り替えられるように実装
