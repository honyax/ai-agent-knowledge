# Claude Code オートコンパクティングの罠と回避術 — 方針が消える原因と対策

## 3行要約

- コンテキストが約80〜83%埋まると自動圧縮が発動し、**序盤に決めたアーキテクチャ方針や制約が要約で消える**
- 根本対策は「重要情報をコンテキスト外に逃がすこと」— CLAUDE.md、手動 `/compact`、Memory MCP の3本柱
- `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=75` で早めに手動発動すると要約品質が上がる

## 自分への関連度: S

長時間タスクで「さっき決めたことを Claude が忘れた」という経験があるなら、これが原因。
CLAUDE.md の書き方と `/compact` のタイミングをすぐ見直せる。

## 詳細

### 症状

- セッション中盤以降、30分前に決めたアーキテクチャ方針と全然違うコードが生成される
- 序盤の「〇〇は使わない」「〇〇の方針で統一する」という制約が無視される

### 原因

コンテキストが **80〜83%** に達するとオートコンパクティングが自動発動。古い会話が要約テキストで圧縮される際、**序盤の詳細な指示・制約・理由が失われやすい**。

### 対策（優先度順）

| 対策 | 方法 | 効果 |
|------|------|------|
| **CLAUDE.md 作成** | プロジェクトルートに方針・規約・作業状態を記載 | 毎ターン自動注入されるため圧縮されない |
| **手動 `/compact`** | 区切りのよいタイミングで観点を指定して実行 | 要約品質を自分でコントロールできる |
| **Memory MCP** | JSON/SQLite ベースの外部記憶に自律的に読み書き | 長期プロジェクトの方針を永続化 |
| **早期発動設定** | `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=75` | 劣化前に圧縮→要約の精度が上がる |

### CLAUDE.md に書くべき内容

- アーキテクチャ方針（使う/使わない技術スタック）
- コーディング規約・命名規則
- 現在の作業状態・完了済みタスク

## 試すなら

1. プロジェクトルートに `CLAUDE.md` を作成し、主要方針を箇条書きで記載
2. 長いセッション中、作業の区切りで `/compact` を実行（観点を指定する）
3. 環境変数 `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=75` を設定して早期発動を試す
4. 重要方針が消えていないかセッション後半で意図的に確認する
