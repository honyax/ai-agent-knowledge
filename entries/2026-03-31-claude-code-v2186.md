# Claude Code v2.1.85–v2.1.86 — Session IDヘッダー、VCS対応、Windows修正

## 3行要約

- `X-Claude-Code-Session-Id` ヘッダーがAPIリクエストに追加され、プロキシ経由でもセッション単位の集計が可能に
- `.jj`（Jujutsu）と `.sl`（Sapling）がVCS除外リストに追加され、Grep・ファイル補完のパフォーマンスが改善
- Windows でスキル呼び出しのたびに設定ファイルが上書きされていた不具合（パフォーマンス低下・config破損）を修正

## 自分への関連度: B

直接ワークフローへの影響は小さいが、VCSサポートの改善とWindowsの設定ファイル修正は安定性に関係する。
プロキシ経由でClaude Code APIを使うケースがあれば Session ID ヘッダーが役立つ。

## 詳細

### v2.1.86 (2026-03-27) の主な変更

**追加:**
- `X-Claude-Code-Session-Id` ヘッダーをAPIリクエストに付与（プロキシがリクエストボディをパースせずにセッションを識別可能）
- `.jj`（Jujutsu）と `.sl`（Sapling）をVCSディレクトリ除外リストに追加

**修正:**
- `--resume` で「tool_use ids were found without tool_result blocks」エラーが発生する問題（v2.1.85以前のセッションに影響）
- プロジェクトルート外のファイル（`~/.claude/CLAUDE.md` 等）への Write/Edit/Read が conditional skills 設定時に失敗する問題
- Windowsでスキル呼び出しのたびに設定ファイルが不必要に上書きされる問題（パフォーマンス低下・config破損リスク）
- `/feedback` コマンドがトランスクリプトファイルの大きいセッションでメモリ不足クラッシュする問題
- `--bare` モードでインタラクティブセッション中にMCPツールがドロップされる問題
- OAuthログインURLのコピーが約20文字しかコピーされない問題
- `deniedMcpServers` 設定が claude.ai MCPサーバーをブロックしない問題
- MCP step-up認可でリフレッシュトークンが存在する場合に失敗する問題

## 試すなら

1. `claude --version` で現在のバージョンを確認
2. `npm update -g @anthropic-ai/claude-code` で最新版に更新
3. Windows ユーザーは設定ファイルの整合性が改善されていることを確認
