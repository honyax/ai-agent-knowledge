# Claude Codeのセキュリティリスク検証 — 実験ノート

> ローカル実行なし。記事精読・考察のみ（2026-03-30、Claude Code Web）

## 攻撃シナリオの整理

- **前提**: 悪意ある開発者が偽パッケージ（例: `fake-logger`）をnpmに公開
- **ベクトル**: 被害者がそのパッケージを含むOSSをcloneし、Claude Codeに機能追加を依頼
- **結果**: Claude Codeは既存コードのパターンを踏襲するため、バックドア（`process.env`全送信）もそのまま採用。採用率100%

## なぜセーフガードが効かないか

直接指示（「バックドアを仕込め」）→ 拒否
既存コードのパターン踏襲 → セキュリティチェックをスキップ

AIは「既存実装の再利用」として処理するため、悪意の判定が働かない。

## 自分の開発環境で気をつけること

- **Unity / C# / NuGet**: npmほど記事の検証はされていないが同様のベクトルは存在する
  → `dotnet list package --vulnerable` を定期実行
- **npm (TypeScript/Web)**: `npm audit` をClaude Code起動前に実行する習慣
- **OSS cloneの際**: Claude Codeに渡す前に依存パッケージを手動確認

## 観察メモ

「AIが書いたコードだから安全」という誤解を正す事例として有用。
逆に言えば、CLAUDE.md に「外部パッケージを追加する前は必ず確認を求めよ」と書いておくことが有効な防御になるかもしれない。
